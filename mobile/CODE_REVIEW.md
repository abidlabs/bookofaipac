# Code review (security, performance, safety)

Review date: aligned with pre-release checklist. Re-run before major releases.

## Security

- **Secrets:** No API keys or tokens in `src/` or `App.tsx`. Remote data uses public JSON on GitHub Pages (`SITE_BASE_URL` in `src/theme.ts`).
- **HTTPS:** `mergedCandidates.ts` fetches only URLs under `SITE_BASE_URL` (HTTPS). No `http://` endpoints in app code.
- **Deep links / browser:** Profile links are built in one place: `src/utils/siteLinks.ts` (`candidateDetailUrl`). Call sites use `Linking.openURL` with that helper so query encoding stays consistent.
- **Storage:** Onboarding flag and candidate cache use `expo-file-system` under app sandboxes; no sensitive credentials stored.
- **Android permissions:** `RECORD_AUDIO` was listed but the app only uses the camera for still capture / OCR. It was removed from `permissions` and **`blockedPermissions`** was added so the merged manifest does not request the microphone (better Play policy alignment). If a future feature needs video with audio, remove the block and re-declare the permission with justification.

## Performance

- **Lists:** `ResultsList` uses `FlatList`; ballot screen uses `SectionList`. Appropriate for scrolling lists.
- **Data:** Candidate matcher loads from bundled JSON with optional background refresh to cache; failures keep bundled data.
- **Optional follow-ups:** Add `fetch` timeouts or `AbortController` if remote JSON ever hangs on poor networks; profile with React DevTools / Flipper if jank appears on low-end devices.

## Safety & policy

- **Copy:** Landing and instructions describe AI/OCR limits and on-device processing; keep store privacy answers aligned with this.
- **“No match” OCR text:** The screen can show raw OCR text when no candidate matches. Decide for your policy whether to keep (debugging UX) or hide/redact in production builds.

## Release hygiene (debug removal)

- No `DEV_FORCE_LANDING` or `__DEV__`-gated navigation in `App.tsx`.
- No “(debug)” copy on the no-match scan label.
- Re-check before shipping:

```bash
rg -n "DEV_|__DEV__|debug\\)|TODO|FIXME|localhost" mobile/src mobile/App.tsx
```

Build scripts under `mobile/scripts/` may log to the terminal; that does not ship in the app bundle.

## Store assets you must produce

These are **not** generated by EAS; create or commission them before filling listings.

| Asset | Notes |
|--------|--------|
| **App icon** | Single square **1024×1024** PNG (no transparency for iOS). Point `app.json` `icon` at it (e.g. `assets/icon.png`). No rounded corners in the file; OS masks them. |
| **Android adaptive icon** | **Foreground** image (safe zone ~66% center) + **background** color already set (`#0c0c0e`). Add `foregroundImage` under `android.adaptiveIcon` in `app.json` when ready. |
| **Splash** | Optional image; you already use solid `splash.backgroundColor`. Replace with a branded image only if desired. |
| **iOS screenshots** | App Store Connect lists required sizes (e.g. **6.7"**, **6.5"**, **5.5"**). Capture from **release** builds on simulators or devices. |
| **Android screenshots** | At least **2** phone screenshots; more for feature placements. Optional **7" / 10"** tablet. |
| **Play feature graphic** | **1024×500** JPG/PNG for the store listing (promo banner). |
| **Promo / descriptions** | Short name, subtitle, full description, keywords (iOS), “what’s new” text per release. |
| **Privacy policy URL** | Public page describing camera, location, and any data handling. Required or expected on both stores. |
| **Support URL / email** | Apple and Google ask for support contact. |
